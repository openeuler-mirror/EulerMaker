# EulerMaker 0.1.0

发布日期：2026-11-16

本版本是 EulerMaker 重构架构的首版，面向 openEuler 及衍生发行版的软件包构建场景。
将依赖链式调用推进的业务流程调整为资源状态驱动的持续调谐，分离管理面、任务调度和构建执行，
统一工程配置、构建状态、产物管理与用户入口。

## 主要能力

### 统一资源模型与控制面

- 使用 Kubernetes 风格的 `metadata/spec/status` 资源模型，通过 API Server 管理业务资源和状态更新。
- Job、Runner 使用 etcd 存储并支持 List/Watch；工程、构建及 IAM 等资源使用 Elasticsearch 存储。
- Build、Snapshot、BuildInfo、BuildGraph、RpmRepo 等对象分别承载构建流程、源码快照、包级结果、依赖图谱和仓库状态。
- Controller Manager 持续调谐资源状态，通过检查点、幂等操作和重试恢复未完成流程，减少对一次性调用链成功的依赖。
- 支持 GET/LIST 字段选择；ES 资源将字段选择下推到 `_source` filtering，减少大对象传输。

### 构建与源码管理

- 支持全量、增量、指定增量和单包构建；增量范围覆盖当前需要重建的软件包及直接依赖它的包。
- 工程使用 `distro` 定义发行版环境、`buildArches` 定义构建架构；创建 BuildInfo 时固化构建镜像。
- Git Server 提供仓库同步和只读 Smart HTTP，Snapshot 将源码引用解析为固定 commit。
- Git 引用采用完整 `refs/...` 字符串，软件包可配置固定 `commitID`。
- 仅含一个软件包的 single 构建支持通过 `ebs.io/git-ref` 指定 PR 等完整引用；引用写入 Snapshot 后固定解析结果。
- 使用原生 `rpmspec` 解析依赖，支持受限的同提交缺失文件补取及有上限的跨仓库并发解析。
- 单包构建直接派发任务，使用已发布仓库及 Bootstrap 仓库提供依赖。
- 非单包构建通过 `Build.spec.publish` 控制是否发布，默认开启；未开启发布时按构建结果收敛为 Success 或 Failed，阶段保持 build。

### 调度、执行与恢复

- Scheduler 根据 Runner 状态、架构、资源请求和剩余可分配资源选择执行机，将资源分配与业务编排分离。
- Runner 支持 Docker 和 containerd 原生 Go Client 后端，提供注册、心跳、任务执行及中止能力。
- Runner 持久化执行完成记录，重启后从上传、日志封账和状态回写阶段继续收尾。
- 日志和产物上传支持幂等确认、可重试错误处理及 PostRun 恢复，降低服务短暂断连导致任务失败的风险。
- 终态与中止任务支持本地工作目录清理；上传失败产物有保留期，并在磁盘使用率达到阈值时清理已有候选。
- Runner 从服务配置周期刷新访问地址，支持内网与外网接入；外网模式使用上游 Git 地址检出固定提交。

### 制品、日志与 RPM 仓库

- Artifact Manager 管理上传清单、实时日志、下载、过程仓物化和正式发布。
- 日志按 Job 分锁，保持正文、索引及检查点的持久化顺序，减少不同任务间的锁竞争。
- 过程仓复用历史内容，检查本批新产物并按 spec 替换旧包；正式发布复用过程仓元数据并切换稳定入口。
- 可选本地 GPG 或 Signatrust RPM 签名，在上传清单封账时执行；下载及物化使用签名后的产物。
- 元数据按需加载，限制历史上传、日志及仓库记录的常驻内存占用。
- 支持按 Job 清理产物和日志，按 Build 清理过程仓与发布版本；删除流程通过 finalizer、状态确认和重试收敛。
- Job 支持历史清理或归档为 OldJob；Build 删除限制、子资源清理和产物清理按各自职责执行。

### 用户入口与运维

- 提供中英文 Web 控制台，展示工程、构建历史、包级结果、日志、依赖图谱和 Runner 资源信息。
- 运维页面集中管理构建配置、资源规则、服务地址、构建脚本和机器账号。
- 支持 OAuth 社区登录，首次登录通过注册页面补全本地账号；启用 OAuth 后关闭本地密码登录与注册。
- Gateway 提供工程级授权及 Runner 身份校验；API Server 拒绝创建或更新为特权运行时配置的 Job。
- 提供 Gateway 对外 OpenAPI 文档及前端只读 API 浏览页面，支持通过 ebsctl 访问资源 API。
- 提供组件到 API Server 的 mTLS 身份认证，以及 API Server 到 etcd、ES 的 TLS/认证部署配置。
- 提供 Kubernetes 部署模板、containerd Runner DaemonSet、证书生成脚本及 ES Mapping check/apply Job。
- Docker Compose 保留本地开发方式，Runner 与控制面分别部署，并提供 TLS 覆盖配置。

## 镜像与部署

Kubernetes 模板使用仓库前缀 `swr.cn-north-4.myhuaweicloud.com/eulermaker/`，以下镜像统一使用 `:0.1.0`：

| 组件 | 镜像名 |
| --- | --- |
| API Server | `ebs-apiserver` |
| Gateway | `ebs-gateway` |
| Controller Manager | `controller-manager` |
| Scheduler | `scheduler` |
| Runner | `runner` |
| Git Server | `git-server` |
| Artifact Manager | `artifact-manager` |
| 前端 | `frontend` |

Mapping check/apply Job 与 API Server 使用同版本镜像。etcd、Elasticsearch 及基础镜像保留各自版本。
发布标签保持不可变，生产环境建议固定镜像 digest。Runner 上报构建时注入的 Git commit，便于定位实际运行代码。

部署步骤见 [Kubernetes 部署说明](../deploy/kubernetes/README.md)。Compose 从本地源码构建，使用方式见[项目 README](../README.md)。

## 部署要求

- Scheduler、Controller Manager 按单活部署；Git Server、Artifact Manager 按单写者方式管理持久化目录。
- 为 etcd、Elasticsearch、Git Server、Artifact Manager 和 Runner 配置持久化存储，规划容量、备份及恢复方案。
- Artifact Manager 使用本地文件系统，管理接口部署在受信任内网。
- `rpmspec` 会执行 spec 中的 Shell/Lua 宏，包源及宏配置应来自可信来源。
- Runner 使用专用构建节点，并根据源码信任范围配置执行环境隔离。
- 生产部署需配置证书、凭据、网络隔离、备份和容量监控。

## 已知安全事项

- `rpmspec` 解析隔离仍需完善。
